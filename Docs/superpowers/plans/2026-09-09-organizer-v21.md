# AI File Organizer V2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an incremental destination-grouped organizer with nested destinations, bounded content understanding, reviewable rules, persistent learning, reliable history, and undo.

**Architecture:** `OrganizationCoordinator` owns a versioned draft and applies results only when the run and item revisions match. Core services discover destinations, extract content, evaluate rules, classify ambiguous items, record learning events, freeze plans, and execute or undo logged operations. SwiftUI renders those states but never manipulates files directly.

**Tech Stack:** Swift 6, SwiftUI, Swift Concurrency, macOS 26, Foundation Models, PDFKit, Vision, Quick Look, GRDB 7.6.1, SQLite.

**Spec:** `docs/superpowers/specs/2026-09-09-organizer-v21-design.md`

## Global Constraints

- Source and library are separate, non-overlapping directories on the same volume.
- Source scanning creates items only for direct children; directories move atomically.
- Destination discovery is bounded to four levels.
- No overwrite, automatic rename, cross-volume move, archive expansion, network AI, or silent folder creation.
- Every file operation comes from a user-confirmed immutable plan.
- Explicit content budgets and cancellation rules in the spec are mandatory.
- Learning consumes successful operation events and is retracted by successful undo.
